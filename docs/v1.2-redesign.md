# IvanDAW v1.2 — Redesign

A new look and three new behaviours: a Windows 95 style UI, sticky notes, and ARM connections (numbered control connectors with a connection window) that replace v1.1's single dotted `ctl` spot and picker.
Sources: Ivan's mocks Frame 1 (full DAW), Frame 2 (cables and connectors), Frame 3 (inspiration board), `design_resources/Без названия.jpg`, and Ivan's notes 1–5.
Workflow as in v1.1.2: commit straight to `main` once `pnpm check` is green; **check** tasks end with "Test on localhost" and wait for Ivan's "ok".

## 1. Look

- **Font.** W95FA (SIL OFL, free for commercial use) is bundled as `apps/daw/public/fonts/w95fa.woff2` + `.woff`, with `OFL.txt` next to it. One `@font-face`; every DAW UI element uses it. Plugin UIs keep their own fonts.
- **Theme tokens.** One CSS file of variables used by canvas and panels:

  | Token | Value | Use |
  | --- | --- | --- |
  | `--w95-desk` | `#387F81` | background |
  | `--w95-face` | `#C0C0C0` | panels, windows, buttons |
  | `--w95-light` / `--w95-dark` | `#FFFFFF` / `#808080` (+ `#000` outer) | bevels: raised = light top-left, dark bottom-right; inset = reversed |
  | `--w95-title` | `#030081` | title bars, white text |
  | `--w95-field` | `#FFFFFF` | inset text fields, dropdowns |
  | `--w95-track` | `#D9D9D9` | slider tracks (pentagon thumb) |
  | `--w95-note` | `#FFFFDE` | sticky note body |
  | `--c-midi` / `--c-arm` / `--c-audio` | `#FFFC12` yellow / `#0600FF` blue / `#FD0007` red | connectors and cables |

- **Building blocks** (plain DOM + CSS, in `panels/w95.ts`): `window(title, buttons)` with navy title bar and `?` `_` `X` buttons; `button`; `field`; `dropdown` (field + arrow button); `slider`; `scrollbar` styling. Canvas and panels both use them.
- **Background.** Plain teal. The v1 grid is dropped.

## 2. Layers

Bottom to top. Each is a sibling element inside the canvas; the first four are inside the zoomed world layer, so they pan and zoom together.

1. Background
2. Plugins (windows)
3. Connector cables
4. Connector info: only the connection window (at most one on screen)
5. Notes (sticky notes, plugin info notes)

Fixed UI (top panel, zoom panel) sits above all world layers and doesn't zoom.
Consequence: cables are drawn over plugin windows, and notes cover everything. Today cables are under nodes.

## 3. Fixed panels

- **Top panel.** Full-width raised grey bar.
  - Left: `Play`/`Pause`, `Stop`, BPM as a white inset field with label `BPM`, beat readout. Same behaviour as today's transport bar (Space, BPM steps, keyboard).
  - BPM is fractional: two decimals (`100.00`), range 40–240. `parseProject` keeps the decimals (today it may round).
  - Right: `Add plugin` (opens today's add menu, restyled as a Win95 menu) and `Sticky note` (creates a note in the middle of the view). Win95 buttons with an icon above a caption. Claude draws both icons: original 32×32 pixel art in the style of the inspiration board (a plug-in card, a yellow notepad), as inline SVG. Hidden in `/play_only`.
- **Zoom panel**, bottom-left. Raised panel with `−`, the zoom `%` (click = 100%), `+`. Replaces the corner readout from v1.1.2. Same zoom maths and snap.
- **The right node panel is removed** (note 1). What it holds moves as in §4.

## 4. Plugin windows

- Each node is a Win95 window: title bar with the plugin name, then `?`, `_`, `X`.
  - `?` opens the plugin's info note (§6).
  - `_` hides / shows the plugin UI (today's `−`/`+`, `uiHidden`).
  - `X` removes the node at once, no confirm. Master has no `X`.
  - Dragging the title bar moves the window. Clicking a window selects it (outline), Delete key still removes.
- Body: the plugin's own UI (unchanged mounting, scaling, hiding), then a footer with Volume and Pan as Win95 sliders, as in the mock.
  - Plugins without their own UI (LFO, Control sliders, Note hold, Note generator, Base sine synth) show their parameters in the window instead: one Win95 row per parameter. This replaces the right panel's parameter list.
  - Footer on instruments, effects, MIDI plugins and Master; not on modulators (LFO, Control sliders, Music Hands), which make no sound or notes of their own.
  - Audio plugins: Volume and Pan act on the audio output, as today.
  - MIDI plugins (output is notes) also get Volume and Pan. Volume scales the velocity of every note they send. Pan sends the standard MIDI pan message (CC10, 0–127, 64 = centre) on each channel the plugin uses; the receiving instrument decides what to do with it (none reads it yet).
- Signal flows left to right: **every input is on the left edge, every output on the right edge**. On each edge, top to bottom: MIDI (yellow), audio (red), then the ARM strip (blue, §7). Connectors are round, in their colour, numbered.
- Errors and loading status, shown today in the node panel, move into the window: a status line under the title bar.
- **On / off checkbox** left of the plugin name in the title bar, Win95 style (white inset box, black tick). Ticked by default. Unticked = the plugin is off: its outputs go silent with a fade (audio) or send nothing (MIDI; notes still sounding get a note off). Saved as `GraphNode.bypass` (unticked = `true`), which the schema already has. Works in `/play_only` too. Master has none.

## 5. Sticky notes

- **Model** (C3 change). `Project.notes?: Note[]`, `Note { id, x, y, w, h, text }` in world px. `parseProject` reads it; old projects load with no notes. Notes are saved with the project.
- **Store** (C4 change). `addNote(at)`, `moveNote`, `resizeNote`, `setNoteText`, `removeNote`.
- **Window.** Same window chrome with the fixed title `Note` and `X` only; body `#FFFFDE` with a Win95 scrollbar when the text is longer than the box. Drag by the title bar, resize from the bottom-right corner.
- **Editing.** Double-click the body → a plain textarea with the raw text. Click outside or Esc → back to the rendered view.
- **Formatting** (note 3), the only two:
  - `**bold**` → bold.
  - `<https://…>` → a link showing the address, opens in a new tab. Only `http`/`https`.
  - Everything else is plain text; line breaks are kept. The renderer is a pure function with Vitest tests and builds DOM nodes, never `innerHTML`, so a note can't inject HTML.
- **Play-only.** Notes show and their links work; they can't be created, edited, moved or deleted.

## 6. Plugin info

- Text for each plugin lives in the DAW's plugin library: a new file `apps/daw/src/model/pluginInfo.ts`, a map from plugin id to note text in the same `**`/`<link>` format. Plugins without an entry show "No description yet." Claude writes a short first draft for every plugin; Ivan edits them later.
- `?` opens an info note next to the window, titled with the plugin name. It is read-only, is not saved in the project, and closes with `X`. A second click on `?` closes it.

## 7. ARM connections

Replaces v1.1's dotted `ctl` spot and its picker (note 5).

- **Which plugins get them.**
  - ARM IN: every plugin with at least one control target: a parameter with `automatable: true`, plus the host's Volume and Pan. That is every plugin except Master.
  - ARM OUT: every plugin with at least one `modulation` out port (LFO, Control sliders).
- **Connectors.** ARM IN strip on the left edge, ARM OUT strip on the right edge, under the MIDI and audio connectors. Each has connectors numbered 1–16. The strip's height follows the window's height; as many connectors as fit are shown, and `<` / `>` page through the rest. Colour: blue.
- **Identity.** A connection is named `"<out plugin name>".<out index> - "<in plugin name>".<in index>`, e.g. `"LFO".1 - "Sine synth".3`. Duplicate plugin names get a suffix (`Sine synth 2`) in this label only.
- **Model** (C3 change). `Project.arms?: ArmLink[]`, `ArmLink { id, from: { node, index }, to: { node, index }, source?: string, target?: string, min: number, max: number }`.
  - `index` is 1–16.
  - `source` is the out plugin's modulation port id. `target` is `ctl:gain`, `ctl:pan` or `ctl:param:<id>` (today's control port ids, so the router logic is reused).
  - `min`/`max` are 0–100 % of the target's range, defaults 0 and 100. Min may be greater than Max: that flips the direction.
  - A link without `source` or `target` is **invalid**: it is saved and drawn, but carries nothing.
  - One ARM IN index takes one link (drawing a second one onto it replaces the first). One ARM OUT index can feed several links.
- **Router.** A valid link sends `source`'s automation events to `target`, mapping 0–1 onto `min`–`max` of the target's normalized range. Same ramps and fades as v1.1 control cables. Two valid links on the same target: last wins, as today.
- **Cables (all kinds: MIDI, audio, ARM).** Dashed 2px in the connector colour. Hover → solid 4px. Click selects a cable; Delete removes the selected cable. Invalid ARM links are drawn dashed grey.
- **Connection window.** Selecting an ARM cable also opens its connection window; it opens by itself when a new ARM link is drawn. Only one is on screen at a time: selecting another ARM cable closes the open one and opens the new one. Selecting anything else, or `X`, closes it. A small Win95 window near the cable middle, titled with the connection name: `Out` dropdown (the out plugin's modulation outputs), `In` dropdown (the in plugin's targets, grouped like today's picker), `Min %` and `Max %` fields (slider + field). No Remove button: Delete removes the selected link.
  - When the out plugin has only one output (LFO), `Out` is filled in already; `In` always waits for a choice.
  - A parameter or Volume / Pan driven by a valid link is greyed out in its window while the link lasts.
- **Bound controls.** As in v1.1, a target driven by a valid link shows as bound in the plugin's footer (Volume / Pan) and its own UI keeps working.
- **Old projects.** No migration: there are no projects to keep. `parseProject` drops cables to `ctl:*` inputs. LFO and Control sliders get ARM OUT and connect to any plugin's ARM IN.
