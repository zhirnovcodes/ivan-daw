# IvanDAW v1.1.2 — Development plan

Three canvas changes: zoom, hide / show a plugin's UI, and limits on how far the camera can pan.
There is no separate design doc: the design for each feature is in this file.
The workflow is the same as v1.1 (`docs/v1.1-plan.md`): commit straight to `main` once `pnpm check` is green. After a **check** task, Claude says what to open and try, then waits for Ivan's "ok".

Localhost check, every time: `git pull`, `pnpm i`, `pnpm dev`, open http://localhost:5173.

## 1. Zoom

- **Camera.** `camera` becomes `{ x, y, z }`. `z` is the scale: 1 = 100%. The world layer's transform becomes `translate(-x·z, -y·z) scale(z)` with `transform-origin: 0 0`. The grid background scales with it.
- **Coordinates.** `toWorld(screen, cam) = screen / z + cam` and `toScreen` is its inverse. These are the only places zoom enters the pointer maths. The other users of camera coordinates follow: `panCamera` (a drag of d screen px moves the camera d / z world px) and `canvasCenter` in `app.ts` (`+ Add` drops new nodes in the middle of the view).
- **Input.**
  - Ctrl + wheel and trackpad pinch (the browser sends pinch as ctrl + wheel) zoom around the pointer, so the world point under the cursor stays put.
  - Plain wheel still pans.
  - Over a plugin's UI the wheel still belongs to the plugin; ctrl + wheel zooms everywhere.
  - Keyboard: `Ctrl/Cmd +` and `Ctrl/Cmd -` zoom around the view centre. `Ctrl/Cmd 0` goes back to 100%. Each one stops the browser's own page zoom.
- **Range.** 25% to 200%, in multiplicative steps (`z *= 2^(-deltaY / k)`), so zooming feels the same at every level.
- **Snap at 0.** The zoom level shown to the user is `log₂ z`, where 0 = 100%. During a gesture, the store keeps a raw level that moves freely. The shown level becomes exactly 0 while the raw level is within ±0.15 of 0 (about 90–111%). So a pinch passing through 100% sticks there for a moment, and pushing further gets past it. Because the raw level keeps moving inside the band, small steps can't trap you at 100%.
- **Readout.** A small `100%` label in the canvas corner. Clicking it resets to 100%.
- **Plugin UIs** are DOM inside the scaled world layer, so they scale with it. The risk: a plugin that does pointer maths from `getBoundingClientRect`, or draws on a `<canvas>`, may drag wrongly or look blurry at zooms other than 100%. Check Beatality's knobs, faders and pack picker at 50% and 150%. Anything that breaks is fixed in Beatality, which is Blocker B as in v1.1. Whether to scale the backing `<canvas>` for crispness is decided there.
- **Not saved.** Zoom, like the pan position, is a view setting. It is not stored in the project file.

## 2. Hide / show a plugin's UI

- **Model.** `GraphNode` gets `uiHidden?: boolean` (missing = shown). `parseProject` reads it, so it is saved with the project. Old projects load unchanged.
- **Action.** `setUiHidden(id, hidden)` in the store.
- **Button.** A `−` button in the node header, only on nodes whose manifest has `ui`. When the UI is hidden it shows `+`. Clicking it doesn't start a node drag.
- **Layout when hidden.**
  - Header, port rows, then the Volume / Pan footer, with no plugin UI in between.
  - `nodeSize` ignores the UI box, so the width goes back to `NODE_W` (180). Beatality shrinks from 746 × ~720 to a small box.
  - The output ports move with the right edge. Cables follow because port centres are always computed from the current width.
- **The plugin stays mounted.** Hiding sets `display: none` on the UI slot. It doesn't call `unmount`, so the plugin keeps its state and nothing changes in `syncPluginUis`.
- **Play-only.** The button works in `/play_only` too: it changes the view, not the sound.

## 3. Pan limits

Today the camera can pan forever in every direction. New rule: **the centre of the view stays inside the bounding box of all nodes, Master included.** That leaves at most half a screen of empty space past the outermost plugin on each side, as asked.

- **Function.** `clampCamera(cam, view, bounds)` in `geometry.ts` is a pure function with unit tests.
  - `view` is the canvas size in screen px. `bounds` is the min / max of every node's box in world px, using `nodeSize`, so a hidden UI counts as hidden.
  - It clamps `x + view.w / (2z)` into `[bounds.left, bounds.right]`, and does the same for y.
  - With zoom, "half a screen" is measured in screen px, so the margin stays half the visible area at every zoom.
- **When it runs.** In `panCamera` and the zoom actions only (the canvas passes the limit as a `fit` function). A node move, a delete, a hide or a window resize never moves the camera by itself.
- **It never jumps.** If the view centre is already outside the bounds (a far node was deleted, or the project opened that way), a pan may move back towards the nodes but not further out. So nothing snaps on the next scroll.
- **Dragging a node** works as in v1.1. The bounds grow with the node, so the limit doesn't fight the drag.
- **`WORLD_MIN`** stays as the hard floor for node positions.
- **Project load.** The camera starts where it does today (0, 0, 100%). The demo is laid out for that view.
